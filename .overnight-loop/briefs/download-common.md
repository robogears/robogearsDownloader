# Rules shared by the four download lanes

You are building one part of the native Swift macOS rewrite of "robogears Downloader" (an Electron app that downloads lossless FLAC from TIDAL; the Swift app replaces it, macOS 15+, Apple Silicon). The Electron code at the repo root is the reference; the checked description of every behaviour is in docs/electron-reference/ (README.md first; download-pipeline.md is the main one for downloads). The owner chose every RECOMMENDED option ("A") in docs/D4_BEHAVIOUR_DECISIONS.md ("just go with all of the recommended stuff for now", 21 Oct 2026) — that document is the spec for behaviour; area 2 ("Downloads, files and batches", items 2.1–2.23) is yours, plus 1.4 (retries, shared pace), 1.6 (sign-in no longer valid), 1.7 (offline mid-batch) and 1.10 where they touch downloads. Where D4 and the Electron reference disagree, D4 wins. docs/spikes/audio-and-tagging.md records what the native FLAC writer does and what needs a live TIDAL check; read its "Recommendation" and "Needs a live TIDAL check" sections.

The SHARED INTERFACE is macos/Packages/RobogearsCore/Sources/RobogearsCore/Download/DownloadContracts.swift: TrackDownloadRequest, SavedQuality, SaveNote, TrackDownloadOutcome, TrackDownloadError (stopsBatch / pausesBatch / rowMessage), FolderDecision, and the three seams TrackDownloading, DownloadFolderPlanning and M4AWriting. Four lanes are being built at the same time against it: "track" (the per-track downloader, conforms to TrackDownloading), "folder" (the download-folder decisions and the final move, conforms to DownloadFolderPlanning), "m4a" (the AAC writer, conforms to M4AWriting) and "batch" (the batch runner, which drives any TrackDownloading). Read that file first. Do NOT rename or remove anything in it. You MAY add to it (a new enum case, a new field with a default value, a doc comment) when your work truly needs it — keep additions minimal and list every one in the result's "contract_changes". Code against the seams of the other lanes through the protocols only, with small stand-ins in your tests; never re-implement another lane's job.

Existing code you build on (read the files you use): TIDAL client in Sources/RobogearsCore/TIDAL/ (HTTPClient with Limits .api/.audio and send(_:retry:) with RetryPolicy; RequestError; TokenKeeper with withAuthorizedRequest and the 401-then-renew-once rule; TIDALAPI wrappers: track, album, playbackInfo(trackID:quality:); Models.swift: TIDALTrack, TIDALAlbum.coverURL(size:), TIDALPlaybackInfo, TIDALAudioQuality; Manifest.swift: TIDALManifest with Location .direct / .segments and Container); Download/ (FLACAudio(downloaded:), FLACAudio(nativeFLAC:), FLACWriter.write(_:tags:coverJPEG:to:), FLACTags, FLACMetadataReader.summary(of:), FMP4FLACExtractor); Audio/AudioProbe.swift (inspect: declared vs decoded frames, verdict); Text/FileNaming.swift (stem, fileName, existingFileCandidates, legacyFileName — sanitising per 2.14) and Text/Normalizer.swift + Matching/ (one Unicode-aware normaliser, ArtistCredit); Library/TagReader.swift (TagReader for FLAC/Ogg/MP4/MP3 tags); State/ (QueueItem with DownloadState, FolderReference + Folders.status / Folders.check, JSONFileStore atomic saves, AppPaths); Audio/SoundPlayer.swift + SoundSynth.swift (the sounds, including finishedWithProblems). Test helpers: Tests/RobogearsCoreTests/TIDALClient/TIDALClientTestSupport.swift (a mock URLProtocol and an injected clock — reuse them), Tests/RobogearsCoreTests/Download/AudioFixture.swift and SyntheticFMP4.swift, and the committed fixtures in Tests/RobogearsCoreTests/Fixtures/audio/ (bts-16-44100.flac and bts-24-96000.flac are native FLAC like TIDAL's BTS streams; dash-24-96000.mp4 and dash-live-16-44100.mp4 are joined DASH FLAC-in-fragmented-MP4 — split one at its box boundaries into an init segment (ftyp+moov) and media segments (each moof+mdat) to stand in for a DASH stream; aac-320.m4a is a plain AAC MP4, dash-aac.mp4 a joined fragmented AAC, ffmpeg-aac.m4a is what the Electron app's FFmpeg wrote; cover.jpg a small JPEG).

Project facts: the Swift package is macos/Packages/RobogearsCore (swift-tools-version 6.0, Swift 6 language mode, macOS 15, Swift Testing: import Testing / @Test / #expect). New fixtures go in Tests/RobogearsCoreTests/Fixtures/<your-subfolder>/ (the Fixtures folder is already a resource; load with Bundle.module.resourceURL!.appendingPathComponent("Fixtures/…"); hidden files are not bundled, so create those at runtime). Tests go in Tests/RobogearsCoreTests/<YourLane>/. Do NOT edit Package.swift, RobogearsCore.swift, the plan or report (OVERNIGHT_LOOP_*.md), the macos/RobogearsDownloader app target, or files outside your assigned ones unless your brief allows it. No third-party dependencies, no bundled FFmpeg. Public API for what the app will call; internal otherwise. Swift 6 strict concurrency must compile clean; every type crossing concurrency domains is Sendable; no data races. Match the calm, readable style of the surrounding code: doc comments explain WHY and cite the D4 item (e.g. "(2.6)") or the reference section; plain words. Never log or print a signed stream URL, a token or the embedded TIDAL client credentials. Writes are atomic or exclusive-create; a failure never leaves something in the download folder that looks like a finished file. The music library folder is read-only — never write there. Rule 2: downloads land flat in the download folder, no subfolders. Rule 3: the file is "<Title>.flac" (or ".m4a"), title only — except the 2.6 clash rule.

Tests: name each test after the scenario it protects ("a second song called Intro is saved under its version"). Every rule gets a test that fails if the rule breaks — check that for the important ones by breaking the code briefly, then restoring it (commit first, or confirm with git diff that everything is restored). No test may touch the real network, TIDAL, Spotify or GitHub, the owner's folders, or the real Application Support folder: use temporary folders and the mock URLProtocol.
