# Download-folder decisions and the final move (lane folder)

Files: new files in Sources/RobogearsCore/Download/ (for example DownloadFolder.swift, ExistingFileCheck.swift, ClashNaming.swift); you may change Sources/RobogearsCore/Text/FileNaming.swift (its header comment still says cards G2-5/G2-6 are pending: the owner has decided — D4 2.6 and 2.7 option A — update the comment and add the clash names there or next to it). Tests in Tests/RobogearsCoreTests/DownloadFolder/.
Build a public DownloadFolder that conforms to DownloadFolderPlanning (one per batch, for request.folder; it may cache one listing of the folder's names per decision). Rules:
1. Names (2.14, 2.6, 2.7): the plain name is FileNaming's "<Title>.flac" / ".m4a" from the bare title. The old app's spellings (FileNaming.existingFileCandidates / legacyFileName) also count as "already here". A name differing only in upper or lower case, or in Unicode composition, counts as taken (APFS is usually case-insensitive, but external drives may not be — compare by your own folded key, not by the file system).
2. Identity of an existing file (2.6): read its tags without loading the cover (FLAC: FLACMetadataReader.summary(of:); .m4a: TagReader). Same recording = same ISRC when both have one; otherwise the same title (compare with the Normalizer, version included as the title tag carries it, 2.7) and an overlapping artist (whole names, ArtistCredit). Files whose title and artist can't be read: .skip(.nameTakenByUnreadableFile) (the row keeps Save As…).
3. Same recording → the quick check (2.3): judge the file's structure, not its tags: FLAC — a valid STREAMINFO whose declared length is within max(2 s, 1%) of TIDAL's duration (when known), and the file ends where it should: find the last frame in the final ~64 KB (sync code 0xFFF8/0xFFF9, a header whose CRC-8 checks) and confirm its CRC-16 footer ends exactly at the end of the file (an ID3v1 tag or trailing zero padding after it is fine to allow; say what you allowed) and that its position is consistent with the declared sample count; .m4a — the top-level boxes add up to the file's size, there is an mdat, and AVFoundation's duration is within the tolerance. Healthy → .skip(.alreadyInFolder(fileName:)). Damaged → .skip(.existingLooksDamaged(fileName:)), the file untouched — unless request.replaceExisting, then move it to the Trash (FileManager.trashItem); if the volume has no Trash, throw an error the UI can turn into D4's "This folder has no Trash. Delete … permanently and download it again?" question (add a TrackDownloadError case for it via contract_changes, or your own public error type).
4. A different song holds the plain name (2.6): try, in this fixed order, "<Title> (<Version>)", "<Title> (<Artist>)", "<Title> (<Album>)" (each sanitised by FileNaming, skipping empty or duplicate candidates), checking each existing candidate by its tags the same way — so re-queueing the second Intro later finds its file and skips it — and choose the first free one, with SaveNote.savedUnderAnotherName(takenName:). If all are taken by other songs, add " 2", " 3"… to the last candidate. Two long titles that shorten to the same name count as a clash (2.14).
5. .m4a and lossless (2.10): with fileExtension nil, an existing healthy same-recording .flac skips; an existing .m4a skips only when request.losslessOnTIDAL == false. With fileExtension .flac and an existing same-recording .m4a, save the FLAC next to it with SaveNote.savedNextToAAC(aacName:) (never touch the .m4a).
6. moveIntoPlace: move the temporary file into the folder in one step with renamex_np(…, RENAME_EXCL) (or renameatx_np) so an existing file is never replaced; if the folded-name check or the rename finds the name taken meanwhile, decide again and use the next free name (adding its notes). The temporary file is on the same volume (the track lane guarantees it); if rename fails with EXDEV, fall back to copy-to-hidden-name-in-folder then exclusive rename, cleaning up on failure. Never leaves a partial file in the folder.
7. The same decision must be usable by the queue for the "In your download folder" badge (2.16): a public, cheap entry point that answers for a row without TIDAL (badge / different song holds the name / nothing), and is safe to call off the main thread.
Also: leftover "….tmp.flac" / "….tmp.m4a" files from the Electron app in the download folder — read D4 2.2 for what to do with them and implement it if it's a folder concern (a helper the app calls), otherwise note it. Tests on files generated in temporary folders (copy the fixtures in Fixtures/audio/ and Fixtures/library/, write tagged FLACs with FLACWriter to create same-title songs, cut files short to make damaged ones, make a case-sensitive clash on a name that differs only by case).
