## Brief

Build:
1. ONE shared pace for TIDAL (1.4): an actor every TIDAL caller goes through (matching, search, previews, downloads; the download and preview code will adopt it at integration, so make it easy to wrap a TIDALAPI or HTTPClient call). Priorities: interactive (a typed search, a preview the person clicked) before matching before downloads before background preloading. A bounded number of requests in flight (choose and justify; the Electron app matched 8 at a time). When any request gets a 429, everyone waits as long as TIDAL asked (Retry-After, up to about 60 s; longer counts as "TIDAL is busy"), and the pace publishes that wait so the batch bar can show it. 5xx, timeouts and dropped connections keep the existing RetryPolicy (1, 2, 4, 8 s); "not found" never retries.
2. The resolver: one add at a time is the app's job (4.18), but every add is cancellable at once (1.11: cancelling stops requests in flight) and streams events as rows are made, so Cancel keeps the finished lines (4.9). Sources: a typed/pasted line or link, a tracklist (text or file bytes, with its name), or a pasted/dropped list that contains links (4.13: each link added as a link, other lines as tracklist lines).
   - Plain text never opens a TIDAL id: it becomes a search (4.1). A single pasted line with a spaced separator ("Blue Lantern - Placeholder Artist") is matched and added directly (4.7, 4.6).
   - Unsupported links are refused with a message that names the service and what is supported (4.2); summaries name the source ("link", the playlist's name, "Exportify CSV", "pasted text").
   - TIDAL links: track; album (every track, in order, paging; an album link that names a track adds just that track, 4.3); playlist (paging, videos skipped); mix links if the parser recognises them (else refused). Rows use TIDAL's data directly — title, version, artists, album, duration, ISRC, explicit, Hi-Res (4.15, 4.16).
   - Spotify links (track, album, playlist; short spotify.link links resolved by following the redirect only to open.spotify.com): read the embed, then match each track on TIDAL: by ISRC first when present, else search "title artist" and TidalMatcher.bestMatch with the reading(s) the matcher expects; an unconfirmed match starts left out (differentArtist), a miss is notOnTIDAL, a failed lookup (busy/offline past retries) is couldNotCheck("Couldn't check: TIDAL was busy") — never "not found" (1.4). Rows show the TIDAL track that will download, with Spotify's own title/artist kept as originalTitle/originalArtist when they differ (4.14). A playlist at the 100-track cap reports it with D4 4.4's honest wording (exact counts when the page has them) so the app can show Open Exportify.
   - Tracklists (4.5, 4.6, 4.17): parse with the existing TracklistParser; match each line like a Spotify track (ISRC and duration columns used when present); progress "Matching N / M" events as each finishes (4.21; also for Spotify and long TIDAL links); concurrency through the pace.
   - Search (4.11): up to ten TIDAL results for a query, each as a ready row with its library mark and whether it's already in the queue (pass the queue's TIDAL ids in).
   - Match Again (4.10): looks a notOnTIDAL or couldNotCheck row up again and returns the replacement row (same id, so it replaces in place); also offer a "search for this row" entry point that returns results to pick from.
   - Library marks (3.x, 4.20): each new row gets its library mark from an injected lookup (LibraryIndexService.match). While the library index isn't ready, rows are added at once marked as "checking library" (an additive QueueItem field) and the resolver offers a function to fill the marks in later when the index arrives; the batch must hold rows whose check is pending (note this for the batch lane in the result).
   - Offline (1.7): an import or link lookup with no internet stops with "No internet connection" and a retryable error that keeps what was pasted or dropped (the source), so Try Again re-runs it.
3. Tests for every rule above, built on the mock URLProtocol with TIDAL and Spotify replies made from invented data (reuse existing fixtures where they fit), including: 8+ concurrent matches sharing the pace and a 429 pausing everyone for its Retry-After; priorities (an interactive search overtaking queued matching); cancel mid-import keeps finished rows and stops in-flight requests; album+track link adds one track; a Spotify playlist at the cap; ISRC-first matching; busy → couldNotCheck not notOnTIDAL; Match Again replacing in place; search badges; the checking-library flow; offline import keeps its source.
